## Epic A — News → Signal in unisona.ai Trader (highest priority)

The only feature area where the repo has real, verified positioning. We already collect
the news (`news.jsonl`, `trading-news.html`, CSF); v1.9 is about *using* it.

### A1 — [DONE, this PR] Deterministic news→deck join + terminal badge · lane: trade · Reason
- `lib/news-signal.js` joins news onto decisive-deck cards (issuer map + title match;
  weather excluded). `.news` signal + recency-weighted conviction nudge. `📰` badge in
  `kalshi-terminal.html`. Unit tests + preview-verified.
- **Acceptance:** met — 6 tests pass; badge renders under Σ₀ line; no false badge on
  weather/no-match; score nudge is monotonic-up only.

### A2 — Semantic news→contract mapping (Verso-parity, LOCAL) · lane: trade · Reason
- Replace the ticker/title join with local embeddings: embed each headline + each open
  market title, cosine-match above a threshold. Use an in-house/local embedding model
  (no cloud), persist vectors in CSF. Covers politics/weather/any-market, not just KPI.
- **Benchmark:** Verso's 73% catalyst accuracy; measure on a hand-labeled set of
  headline→market pairs. **Acceptance:** ≥ parity on the labeled set, runs offline.

### A3 — Local FinBERT sentiment, drop keyword `scoreImpact()` · lane: trade · Observe
- Swap `news-collector.js` keyword impact for local FinBERT (ProsusAI, Apache-2.0);
  keep keyword scorer as zero-dep fallback. Write `sentiment`+confidence back to
  `news.jsonl`. Reason: current impact is a flat keyword heuristic (most records = 35).
- **Acceptance:** sentiment varies meaningfully across corpus; runs CPU-only, offline.

### A4 — CSF news→trade memory surfaced in the deck (THE WEDGE) · lane: trade · Converge
- Use the existing `news-relations.jsonl` to show, on a card, "last time similar news
  hit this market, outcome was X." This is the one thing no funded competitor (Verso,
  Benzinga) offers — local memory of *your* outcomes.
- **Acceptance:** card shows a grounded prior when a matching relation exists.

### A5 — [LEGAL/BLOCKER] Route shipped news off Finnhub free tier · lane: alex · —
- Finnhub free tier **prohibits commercial use**; unisona.ai is monetized. Default the
  shipped signal to Yahoo/Alpaca + local FinBERT; gate Finnhub behind a paid key or
  dev-only flag. Flag Yahoo ToS as a product-legal decision for Alex.
- **Acceptance:** no Finnhub-sourced data reaches a paid surface without a paid key.

## Epic B — Financial Overview analytics (medium; borrow the math, defer polish)

Commodity feature — every tool has an equity curve. All metrics derive from `fills`/
`positions`/`balance` the repo already logs. **Borrow Ghostfolio's metric *definitions*
only — adopt ZERO Ghostfolio code (AGPLv3 network-copyleft would infect the whole app).**

### B1 — `lib/kalshi-analytics.js`: derived performance metrics · lane: trade · Verify
- From `fills`: equity curve (running cumsum), max drawdown (peak-to-trough), ROAI
  windows (Today/WTD/MTD/YTD/Max), holding-time. From `positions`: exposure-by-category.
  Surface buying-power/available-cash already returned by `/balance`.
- **Acceptance:** metrics match a hand-computed fixture; pure functions, unit-tested.

### B2 — "Overview" tab inside the existing terminal · lane: trade · Verify
- Extend the collapsible account panel into an Overview tab — **not** a new page.
  Hand-rolled SVG equity curve + drawdown shade, allocation bars, ROAI tiles. Escalate
  to **uPlot (MIT, ~40KB, zero-dep)** only if >3 chart types emerge. No framework.
- **Acceptance:** renders from B1 data; no new route tree; no external CSS/JS host.

## Epic C — Resume ATS scoring (low priority; cheap freebie, not a differentiator)

OSS already saturates "local-first resume builder" (Resume Matcher on Ollama; resume-ai
"no cloud, no tracking"). Local-first is table stakes here. But the gap is ~40 lines
because the coverage math already exists.

### C1 — ATS match-score fields in `tailor_highlights()` · lane: create · Verify
- The skill already computes `confidence = have/len(required)`. Emit it as a labeled
  **ATS score** + a first-class **missing-keywords** list (the Jobscan/Rezi primitive) +
  static **format warnings** (hidden text, multi-column, non-standard headers — pattern
  from resume-ai). Reimplement Resume Matcher's *scoring pattern* (Apache-2.0); do NOT
  adopt its Ollama/LLM code (violates "NO LLM inside skill").
- **Acceptance:** `{ats_score, missing_keywords[], format_warnings[]}` on the existing
  `TailoringResult`; surfaced through the `job_application` persona; skill stays
  deterministic; existing 21 tests still pass.
- **Do NOT build:** semantic-similarity scoring, "detect which ATS," a new skill/persona.
