- **`setUserRole` / the profile store now resolve to one fixed root, not the launch directory (#3088)** — `lib/user-profiles.js` computed its store as `process.cwd()/data/profiles`, so a `setUserRole` CLI run from `apps/lantern-garage` wrote a *different* file than a server launched from the repo root read: role changes silently never took effect and profile data split across two roots (a split that had already caused two incidents). It now roots at `app-paths.dataRoot()` — the existing #1946 G2 anchor (`<repoRoot>/data`, or `UNISONA_STATE_DIR`), which is cwd-independent, so a CLI script and the server always agree. Loading warns if the old cwd-relative location still holds data, so an operator can merge/remove it rather than orphan accounts. The eight profile-store tests switch from `chdir`-based isolation to `UNISONA_STATE_DIR` (same temp dir → identical store path). Scoped to the profile store — the other `process.cwd()`-relative modules are a mechanical follow-up on the same #1946 anchor.
