### Fixed

- watch/trader: **a chart slot for a symbol the list no longer carries disappears instead of charting nothing forever — and the watch page no longer crashes signed-in visitors.** Chart slots persist in the browser while the watchlist/tradelist lives server-side, so the two drift (a server-data reset, or a symbol removed from the list): the collector only polls listed symbols, so the orphaned slot sat on "Waiting for price data" indefinitely (#3514). The list is now the slots' source of truth — once it loads, any slot it doesn't carry is pruned and the deck refills with real list symbols; charting a new symbol still goes through the slot editor, which registers it on the list (with the tradelist-edit warning on the trader page). The overlay also stopped lying while data genuinely is pending: "Waiting for price data" only before the feed's first answer, "No live feed for X" after it. Separately, `watch.html`'s `setOrderSymbol` still wrote to the order-ticket form that was cut when the page split from the trader as the watch-only surface — every signed-in visit threw `Cannot set properties of null` at boot (the one console error in the issue capture). It now no-ops without the panel, matching the page's own `openOrderTicket` redirect.
