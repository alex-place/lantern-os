### Fixed

- Signup no longer silently locks users out when the mailer is configured but failing (#3021 code half). Previously the confirmation email was fire-and-forget and emailDelivery was derived from mailerConfigured() (config present), so a configured-but-failing provider (e.g. Resend key set but MAIL_FROM domain unverified → 401) reported 'sent' while nothing arrived, the code was written nowhere, and login stayed 403 email_unverified forever. Now the send is awaited with a bounded wait and emailDelivery reflects the REAL result (sent/sending/failed/logged); on a provider failure the mailer records the code to data/mail-outbox.jsonl for operator recovery instead of swallowing it. Verified live: failing Resend → emailDelivery:'failed' + code in the outbox + no public leak. The DNS verification of the sending domain remains a founder/ops task.
