### Changed

- test: added a regression guard for the #2617 registration anti-enumeration invariant in `tests/test_local_auth_flow.js`. The fix (existing-email signup returns the same generic `202 pendingVerification` a fresh signup gets — never a `409 email_taken` — while separately emailing the real owner a reset link) shipped and closed #2617, but no test pinned it, so a future refactor could silently reintroduce the enumeration tell. The new case asserts a duplicate registration returns `202` (equal to a fresh signup's status, never `409`), carries no `error`, does not sign anyone in, and never textually reveals the account exists. Documents the known accepted residual (proxied no-SMTP host: `201` auto-admit vs `202`, an inherent tension with the #2065 no-mailer guard; production runs with SMTP where both are `202`).
