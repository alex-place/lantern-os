### Added

- cicd: **master's head now deploys to Railway from GitHub — and only behind green CI.** A new `deploy-railway.yml` workflow fires when the "CI" workflow completes on `master` and deploys the exact commit CI validated, only on success — so a red master can never ship, which Railway's own push-triggered repo watcher cannot promise. Superseded in-flight deploys are cancelled rather than queued (the head moving is the trigger, so only the newest matters), and when a `RAILWAY_APP_URL` repo variable is set the run passes only after the **serving host** answers `/api/version` with the deployed commit — the post-outage rule that a deploy is verified where it serves, not by a green build. The pipeline skips cleanly (green, with a notice) until the operator wires a `RAILWAY_TOKEN` repo secret, so activation is a one-time dashboard task, not a code change. The existing Railway build plan (#3401's `railway.json` + `nixpacks.toml` + `.railwayignore`) is untouched; `CLAUDE.md`'s stale "no Railway config exists" note now describes the real pipeline, including the `SESSION_SECRET` boot requirement and the `/app/data` volume.
