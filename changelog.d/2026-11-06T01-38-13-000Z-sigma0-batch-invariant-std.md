### Fixed

- sigma0: a row of a batch now reads the same anisotropy and the same C3 floor as the same row run alone. Both took the unbiased std from `Tensor.std`, which on CPU reduces a batch of one in two passes and each row of a larger batch by Welford's update, so in float64 one Σ could read a different a(Σ) alone than beside a copy of itself (260 of 500 random rows at d = 4), on either side of ε_a. They now take it from `mean` and a `sum` of squared deviations, accumulated in float64 as `std` does (`_unbiased_std` in `src/cio_sde/collapse.py`). `test_a_batch_is_independent_trajectories` now holds bit for bit with Σ0[1] = 3·I and 2·I, where row 1 used to differ, and a new test reads 500 random Σ per dimension alone, beside a copy and in the batch. The change moves a(Σ) by at most 3.3·10⁻¹⁶ and the floor by at most 2.6·10⁻¹⁵ relative in float64, alone or in a batch, so every float64 run in which the operator fires moves by about an ulp; float32 values do not move, and the float32 placebo control reads as before. What still rounds a row differently in a batch is matrix multiplication: `LinearDynamics`' own drift x·Aᵀ once A's products are not exact, the layers of the neural `Dynamics` and of a nonzero policy, and, from d ≈ 50 with MKL, the covariance step's batched products. So a batched run equals its rows run alone bit for bit wherever its matrix products are exact, and otherwise only to rounding. Theorem C3 and its Lean bridge are unchanged.
