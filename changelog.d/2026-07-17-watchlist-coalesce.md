### Fixed

- stock-trader.html (#2491): coalesced the `/api/trading/watchlist-prices` load burst. ~10 independent init paths each call `loadWatchlistPrices()` within ~0.25s on trader load; the old `pricesLoading` guard only blocked *overlapping* calls, and each completed fast enough (localhost) that none overlapped — so the parameterless endpoint got hit ~10×. A thin coalescing wrapper now (1) shares one in-flight request across truly-concurrent callers and (2) skips a re-fetch within a 2s freshness window (well under the 3s poll + 30s full-refresh, so neither is starved). Callers that mutate the watchlist first (add/remove ticker) pass `{force:true}` so the freshness window can't hide the changed ticker set. Verified live in the dev preview: Resource Timing shows a **single** watchlist-prices request on initial load (then the normal 3s poll); a 6-way concurrent burst and 3 sequential calls each collapse to 1 fetch, `{force:true}` bypasses the window, and the watchlist still renders all 16 tickers.
