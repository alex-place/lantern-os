### Fixed

- security/csrf: **`/billing/success` no longer mutates state on a GET** (#2648). Stripe redirects the browser to the success URL with a cross-site top-level GET, and the handler used that GET to run an eager-sync (retrieve the Checkout Session → `applyStripeState`/`syncSubscription`) — with the `client_reference_id === userId` ownership check as the *sole* CSRF barrier. The GET is now a pure redirect that only forwards the session id to `/pricing.html?checkout=success&cs=…`; the eager-sync moved to a new authenticated same-origin **`POST /api/billing/sync`** (pricing.html fires it on return). The ownership check remains as defense-in-depth, not the load-bearing barrier. Idempotent — the webhook stays the source of truth. Verified: billing lifecycle E2E updated to the POST flow, 27/27 pass.
