### Added

- trader: **email delivery for fired alerts** (#3249, email half) — opt-in per user from the Alerts tab's new Delivery row, sent through the existing mailer (Resend or SMTP — no new provider) with the alert message and a manage link back to `#alerts`. Self-skipping and honest: off by default, silently falls back to the in-app feed when no mailer is configured or the account has no email (and the UI says which), and a rolling-hour rate cap (`ALERT_EMAIL_HOURLY_CAP`, default 6) is consumed **before** sending so a bug can never spam a mailbox. Delivery is fire-and-forget from the scan loop — the in-app feed row is already durable whatever email does. Web-push deliberately not included: it needs a VAPID dependency + service worker (a dependency decision, not a rider).
