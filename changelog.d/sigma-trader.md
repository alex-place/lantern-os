### Changed
- **The Champion allocation engine is now the "Sigma Trader," on its OWN broker account.** Renamed `lib/champion-book.js` → `lib/sigma-trader.js`, endpoints `/api/trading/sigma-trader` (+ `/api/trading/champion` kept as a one-release alias), env `CHAMPION_ARM` → `SIGMA_ARM`, ledger `sigma-trader.jsonl`. Critically, the engine now resolves a **dedicated account** (`SIGMA_ALPACA_API_KEY_ID/_SECRET`, or its own connected OAuth under the `sigma-trader` identity) and **deliberately never falls back to the shared server keys** — so it can no longer collide with the day-trader on the same paper book (the "insufficient qty available" conflict found while testing #2707). With no dedicated account set, it plans but refuses to place a single order. Verified live: with the shared day-trader keys present, the Sigma identity resolves to no account and an armed rebalance refuses (`no_dedicated_account`). Tests: `test/sigma-trader.test.js` (11 — incl. the no-dedicated-account refusal). To fully isolate, set `SIGMA_ALPACA_*` to a SEPARATE Alpaca paper account.
