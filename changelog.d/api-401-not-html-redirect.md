- **Unauthenticated `/api/*` requests get `401` JSON instead of a `302` to the HTML login page (#2980)** — every auth gate (`requireAuth` / `requireRole` / `requireEntitlement` / `requireStaff`) answered a session-less request with `302 → /auth.html`, even for `fetch()`/XHR calls. The browser follows the redirect transparently, so client code received a `200` + login *HTML* where it expected JSON (failing `JSON.parse`, or silently reading it as empty data), and a guest viewing `stock-trader.html` re-downloaded the whole `auth.html` page on every `watchlist-prices` poll, forever. The gates now return `401 {error:"auth_required", returnTo}` when the request is under `/api/`, is a non-`navigate` `Sec-Fetch-Mode` (fetch/XHR), or `Accept`s JSON-not-HTML; a genuine top-level document navigation still `302`s so a human lands on the login screen. Verified live (guest `/api/trading/*` → `401` JSON; `/kalshi-terminal.html` nav → `302`) and unit-tested (`api-401-not-html.test.js`). Also clears the empty guest "MARKET NEWS" block on explore.html (`/api/trading/news` was in the redirect set).
