### Fixed

- routes: three route-layer robustness bugs from the 2026-07-16 profiles/login audit. **(#2650)** `auth.js` `readJsonBody` and **(#2649)** `profiles.js` `readBody` called `req.destroy()` when the 1MB size cap tripped — but `destroy()` kills the `'data'`/`'end'` events, so the returned promise never settled and the awaiting async handler hung forever (a client streaming >1MB could pin a request indefinitely). Both readers now `resolve(null)` on the cap *and* on teardown (`'close'`, which `destroy()` does fire); `resolve()` is idempotent so the end/error/close races are harmless, and the handler answers instead of leaking. **(#2651)** `GET /api/profiles/me` returned `200` with a literal `null` body when a live session named a profile id that no longer resolved (index reset / migration) — clients (`profile.html`, the nav badge) then did `(await res.json()).role` → `TypeError` instead of a recoverable signed-out state. It now answers `401 unknown_account` (`signedOut: true`), mirroring the change-password handler's `unknown_account` branch, so the client treats it as logged-out. Covered by `apps/lantern-garage/test/route-body-robustness.test.js`, which drives the real handlers (oversize/teardown streams + a ghost session) and asserts settlement + the 401 contract.
